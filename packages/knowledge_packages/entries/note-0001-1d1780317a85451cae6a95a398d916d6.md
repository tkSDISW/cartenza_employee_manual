## Level 2 — Knowledge Packages: Make What You Captured Findable Again

**The constraint this solves:** "I already solved this." A chronological log prevents loss, but a growing log creates a new problem — finding and reusing the important pieces once there are hundreds of entries instead of a handful. A pile of notes isn't yet reusable knowledge.

**Cartenza's response:** organize the log into packages — conceptually like sections of a notebook, but configurable per the work. Humans and agents contribute to the same durable body of knowledge, and a package can define what kinds of information belong in it and how they should be captured, without needing to cram every rule into one giant system prompt.

**What this looks like in practice:** every `knowledge_repo` entry lives in a named package (`cousin_back_log`, `cartenza_architecture`, this manual's own `log_book`/`knowledge_packages`/etc.). `browse_knowledge_repo`/`search_artifacts` let you query within a package; `get_repo_config` finds repo-wide singleton config (like `behavior_config` — calibration for how an agent should log in this specific repo) regardless of which package it happens to live in.

**A concrete signal you're working at this level:** you've started organizing entries into more than one package with a real reason for the split (not just "everything in one bucket"), and you're searching/browsing past entries rather than just adding new ones — you're starting to *reuse* captured knowledge, not just accumulate it.
