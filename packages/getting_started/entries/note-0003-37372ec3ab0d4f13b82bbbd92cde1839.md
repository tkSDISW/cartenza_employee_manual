## Connecting to a Repo: PATs, Connect Codes, and Sessions

Before you can read or write anything, you have to get at a repo. There are two ways, and the second one costs a human their attention — so it's worth understanding what you're spending.

**Every `begin_connect` interrupts a person.** They stop, open a browser, and authorize. One real session generated roughly a dozen of these in a single afternoon for what the user experienced as one continuous piece of work (`After_Treatment_System_Notebook`/`Fabric_MCP_Issues`, OBS-0003). Some of that was unavoidable. A good part was not, and this page exists so the avoidable part stops happening.

### Which path are you on?

| Situation | Use |
|---|---|
| You can safely pass a PAT as a tool argument (e.g. Claude Code, PAT read from an environment variable, never authored by you) | `pat=` directly on `clone_knowledge_repo` / `github_pat=` on `clone_capella_repo` |
| Your own safety layer blocks credential-shaped arguments (e.g. ChatGPT) | `begin_connect(agent_id, remote_url, branch)`, then `clone_*(connect_code=...)` |

If you're on the second path: **don't try to disguise or reformat the credential to get it past your own safety layer.** That layer is right. `begin_connect` is the supported way through — it returns a plain, non-secret URL you can print verbatim (`cousin_back_log`/NOTE-0062).

### Three rules that save the human real interruptions

**1. A failed clone does NOT consume your connect code.** The code is spent only when a clone actually succeeds. So if `clone_knowledge_repo`/`clone_capella_repo` fails — wrong branch, empty repo, no `.aird` file, repo not pushed yet — **retry with the same code.** Do not go back and ask for a new link. The error message now tells you this explicitly; before it did, one user discovered it by trial and quite reasonably decided not to rely on it, buying extra browser trips they didn't owe.

**2. A code expires 15 minutes after `begin_connect`.** That is the *only* condition, besides a successful clone, under which the user genuinely needs to issue a new one. If you've been thinking for a while before calling `clone_*`, the code may have gone stale — that's a real reissue, not a wasted one.

**3. Prefer "Connect with GitHub" over pasting a PAT.** When the user reaches the connect page they get both options. The GitHub authorization covers *their other repos too*, so on `capella-fabric` a model's library repos need no further credential — `add_dependency_repo` just works. A pasted PAT is a single-use snapshot, cleared when the code is consumed, so every dependency would need its own code and its own browser trip.

### Sessions are cheap; authorizations are not

A `session_id` is not a login. It's a handle to a server-side clone, and it can go away:

- `knowledge_repo` sessions live in memory and vanish when the server restarts, with no warning.
- `capella-fabric` sessions are swept from disk roughly 4 hours after last use.

Either way you get "Unknown session_id" on the next call. On the direct-PAT path, re-cloning costs nothing. **On the connect path, a lost session costs a fresh human authorization** — so batch related work into one session rather than cloning between every step, and don't call `cleanup_session` while a follow-up is likely (see the Session Cleanup guidance in the system prompt).

Also note sessions are **per server**. Moving between "log this in the notebook" (`knowledge_repo`) and "change the model" (`capella-fabric`) means two independent sessions and two independent authorizations, even though both repos belong to the same person. That multiplication is the single biggest driver of the dozen-authorizations afternoon.

### If something goes wrong

`begin_connect` refuses anything outside the agent's registered scope — that check is what makes the returned URL safe to print. If it says the agent has no scope for a repo, the fix is on the human's side at `/onboarding/agents`, not something you can work around. Likewise "No registered agent with id ..." means the `agent_id` you were given isn't registered *in that environment* (dev and production have separate registries).
