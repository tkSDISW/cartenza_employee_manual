## Seeing Your Repo's Config: the Chips on the Notebook View

Open `/notebook` for a repo and you'll find a short row of chips just under the header, before the package rows. They show the three pieces of repo-level config described in `knowledge_packages`:

| Chip | What it is |
|---|---|
| **Purpose** | What this repo is for, and who it serves |
| **Behavior** | How much rigor, what "good" looks like here |
| **Vibe** | How the notebook itself renders — the `notebook_config` entry |

**Why they exist:** config entries live as ordinary entries inside whichever package they happened to be logged in. An agent finds them with `get_repo_config`, which scans every package. A person browsing had no equivalent, so it was easy to forget the config existed at all — and forgetting is how a second one gets created.

**Three states, each meaning something different:**

- **Gold** — set. The chip links straight to the entry, in the package it really lives in.
- **Dashed and muted** — not set for this repo. Information, not a demand: a missing config never blocks work, and nothing here is broken.
- **Orange, bold, "conflict"** — more than one entry of that type exists. This one matters: `get_repo_config` stops returning that config to **every** caller until a human merges or removes one. If you see it, fix it; don't leave it.

### Refresh, and why you may need it

The viewer works from its own clone of the repo, and that clone only updates when you ask it to. An entry written by an agent through an MCP session goes to the remote — it will not appear here until you pull.

So if an agent has just written something and the page doesn't show it, **use Refresh** (beside the window pills, top right). That is expected behaviour, not a fault. It applies to the chips as much as to the package counts: a repo whose `notebook_config` was added a minute ago will show Vibe as unset until you refresh.

One consequence worth recognising: a `?vibe=` parameter in the URL **previews** a vibe without changing the stored config. If the page renders one way while the Vibe chip says nothing is set, that is what happened — a preview, not a contradiction.

**Reference:** `knowledge_packages` package (what these config entries are, and repo-wide discovery), `establishing_purpose` package (how to establish them for a repo that has none), this package's entry on finding purpose and behavior_config before you write.
