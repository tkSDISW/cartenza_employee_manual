## What Is This Manual, and How Should You Use It?

**This is not `cartenza_capabilities`.** That package is the raw design log — every addendum, every course-correction, valuable for understanding *why* Cartenza's architecture is shaped the way it is, but not meant to orient someone new. This manual is the curated, groomed counterpart: role and behavior content, starting from what Cousin (Claude Code's own working instance) already maintains for himself (`cousin_repo`/`cartenza_mcp`/bcfg-0001), generalized for anyone stepping into Cartenza work.

**Three different ways to use this manual, depending on who you are — deliberately, not by accident:**

- **If you're an agent (a fresh Claude session, ChatGPT, or anything else) doing due diligence before engaging with a Cartenza-connected repo:** you can read this whole manual in one pass, right now, before doing anything else. Nothing here is gated behind a maturity signal — completeness serves you, staging doesn't apply.
- **If you're a human new to Cartenza:** don't feel obligated to read this cover to cover first. The intended experience is closer to Claude Code's own onboarding — explore as questions come up, rather than memorize a long document upfront. Start with "Which MCP Server Do I Use?" (this package) if you're actively working, or the `log_book` package if you want the conceptual starting point.
- **If you're a curious, advanced user who wants to see everything laid out on demand:** it's all here — nothing is hidden from someone who goes looking, even if the default experience for a brand-new user is lighter-touch.

**The five packages below this one — `log_book`, `knowledge_packages`, `routines`, `playbooks`, `projects` — are Cartenza's own "staircase":** each one exists because solving the previous constraint revealed the next. They're ordered deliberately; reading them in order tells the real story of why Cartenza is shaped the way it is, not just what each piece does.

| Level | The constraint it solves |
|---|---|
| 1 — `log_book` | Conversations and context get forgotten between sessions |
| 2 — `knowledge_packages` | Captured information is hard to find and reuse once it accumulates |
| 3 — `routines` | Successful workflows are tedious to repeat by hand |
| 4 — `playbooks` | Coordinating multiple people and agents around shared ways of working is hard |
| 5 — `projects` | Good practices stay local instead of compounding across an organization |

**Not yet built into this manual (by design, this stage):** a mechanism that watches your own behavior and proactively suggests the matching section just as you need it, rather than you having to browse here yourself. That's planned (`cousin_back_log`/note-0050), but the detection logic lives in system-prompt/instructions layers, not in this repo — this repo is content only, for now, deliberately kept as a plain, inspectable git repo rather than hidden server-side (`Tony_BackLog`/NOTE-0035's "hide the jewels" tradeoff, accepted deliberately for now).

**Reference:** `cousin_back_log`/note-0050 (the full design history — staging plan, JIT mechanism design, audience differentiation, governance considerations), `cartenza_capabilities`/NOTE-0019, NOTE-0020 (the original staircase reasoning, in full), `cousin_repo`/`cartenza_mcp`/bcfg-0001 (this manual's own starting-point content and style).
