## Establishing a Repo's Purpose and Behavior Config — Why This Matters

**The problem this solves:** for a while, "who is this Cartenza repo for, and how should it behave" only ever lived as static text — a whole bespoke system-prompt document per persona (Heather, Entrepreneur, Marketing, and others), hand-authored and pasted into a client's Project instructions. `cousin_back_log`/note-0031 named this the wrong shape directly: **identity-authored, not config-layered.** A repo's actual purpose and behavior calibration should be something an agent *discovers* by connecting to the repo, not something re-typed into a document per user, per persona, forever.

**What changed:** `purpose` and `behavior_config` are real, revisable singleton entries (`cousin_back_log`/note-0052) — free-text, no required schema, "the key a piece is written in," same discovery mechanism (`get_repo_config`) as any other repo-level config. This package is about the missing piece: **how an agent actually establishes them for a new or under-configured repo**, generalized across whatever kind of user connects — not tied to one persona's static document.

**Reference:** `cousin_back_log`/note-0031 (identity-authored vs. config-layered), note-0052 (Purpose's real shipped shape), `getting_started` package (the manual's own overview).
