## capella-fabric: What It Won't Do, and Why

A tool's limits are easier to live with once you know which are deliberate and which come from somewhere else. Knowing them up front also saves an agent from retrying something that can't work.

### Deliberate: exchanges, component exchanges and physical links can't be created by patch

`apply_model_patch` rejects creating **functional exchanges, component exchanges and physical links**, with a clear error.

**Why:** these connect **ports**, and this tool doesn't create or check ports. An exchange created without correct ports looks fine but isn't valid, and it's harder to find and undo than to draw correctly in the first place. The Capella desktop editor creates the ports as part of drawing the connection, which is why that's where these belong.

**What still works:** renaming or re-describing an **existing** exchange or link, and allocating an exchange item onto an existing functional exchange.

### A known upstream limit: child physical functions under a physical function

**You can't create a physical function as a child of another physical function**, with any patch shape.

**Why:** this is a gap in capellambse, the library capella-fabric is built on, not a patch mistake. Its physical-layer metamodel doesn't provide the attribute such a child would attach to. The server recognizes the case and explains it, rather than passing on a confusing low-level error.

**What to do instead:** create the function under the logical layer's root function, where the identical patch works, and realize it onto the physical layer, or create it in the Capella desktop editor. You *can* target the containing physical function package, but that makes a **sibling** of the root physical function, not a child. That's a different structure, so choose it deliberately if you choose it at all.

### Not supported: custom cardinality

New properties and exchange item elements get a **minimum and maximum cardinality of 1**, matching what Capella itself defaults to. **A different cardinality, such as a minimum of 0, can't be set by patch.** Set it in the Capella desktop editor.

### Handled for you, so you don't need to

Several things that are easy to get wrong are taken care of automatically:

- **Element types are filled in when you leave them out.** A function added to a layer gets that layer's function type, and a component gets that layer's component type. Without this, the underlying library would create malformed elements instead. An explicit type you provide is always respected.
- **At the physical layer, components are added in the right place.** The old attribute for child components on that layer is deprecated in current capellambse; the server uses the real containment.
- **A new property value group is applied to its parent automatically**, in the same patch. You don't need a second patch before Capella treats the group as applied.
- **Default cardinality of 1** on new properties and exchange item elements, as above.

### What looks like a problem but isn't

**Descriptions containing apostrophes or quotes look double-escaped in the raw model file.** That's correct. A description is HTML content, so the character is HTML-encoded, and the file's XML then escapes the resulting `&` character. Capella's own hand-written content looks exactly the same.
